Descrição das regras sintáticas do Elgol

Uma expressão matemática envolve uma atribuição seguida de operadores. Observe que a linguagem Elgol faz distinção entre variáveis (id) e nomes de funções (não são id porque usam outra regra léxica para definir)

Uma função não pode ser alvo de uma expressão, mas pode fazer parte dela como operando.

Exemplos:

 Lixo = _Z_ .

 _NEG_ Breca .

 Bare = Lixo + Breca x _Z_ - 45 / 5 .

 Lixo = Bare EXP 3 .

 Teste = Bare + Breca x 45 + $Soma(30,40) .

Sempre terminando com . e sempre um único comando por linha.

A linguagem Elgol é diferente porque não impõe precedência de operadores, Programar no Elgol é para programadores avançados que sabem disso. Na geração de código (etapa que vocês não irão implementar) a expressão acima fará primeiro Bare + Breca desrespeitando assim até mesmo as regras de precedência matemáticas existentes. O programador deverá escrever o código já na precedência desejada pois o Elgol nada respeitará. Os parênteses no Elgol apenas são usados para parâmetros de função e não para impor precedência. No caso, o programador deveria ter escrito a expressão anterior, para respeitar as precedências matemáticas.

Não há um limite de operadores em uma expressão matemática, mas somente um id pode receber o resultado de uma expressão.

Funções

A definição de uma função começa tendo o seu tipo (neste momento apenas o tipo DECIMAL é suportado, mas o Elgol está em desenvolvimento) seguido dos parâmetros, como no C. Os parâmetros de uma função também são identificadores (necessariamente). A palavra reservada elgio indica o resultado da função (não tem return) e funciona quase como um identificador (mas é palavra reservada). Uma função não precisa retornar nada, logo, não é um erro semântico a falta desta atribuição (mesmo que semântica não faz parte deste trabalho).

DECIMAL $Soma (DECIMAL Numm, DECIMAL Dois) .
inicio .
   elgio = Numm + Dois .
fim.

O uso da palavra reservada elgio na função não é obrigatória, mas se for usada ela é como uma expressão matemática, porém como elgio antes da atribuição e sem a possibilidade de ter novas funções como operando. Se houver uma nova função na expressão elgio, é um erro de sintaxe:

DECIMAL $Fazalgo (DECIMAL Numm, DECIMAL Dois) .
inicio .
   elgio = 20 x $Soma(Numm, Dois) .
fim.

No código acima temos um erro de sintaxe porque $Soma (função) não pode ser operando. Ou seja, na regra para a palavra reservada elgio não pode ter token de função (#ficaadica)

DECIMAL $Fazalgo (DECIMAL Numm, DECIMAL Dois).
inicio.
   DECIMAL Temp.
   Temp = 20 x $Soma(Numm, Dois).
   elgio = Temp.
fim.

Já neste anterior, sem erro de sintaxe, pois se criou uma variável Temp para receber o resultado da função.

A linguagem Elgol não aceita recursividade, então, se no código da função houver uma chamada para a mesma função, isso é erro semântico (novamente, não alvo deste trabalho)

Uma função não pode ser parâmetro de outra função, ou seja, na invocação de uma função apenas podem existir números ou ids (ou a palavra reservada _Z_).

enquanto

A forma dele é sempre:

enquanto expressão_lógica.

inicio.

fim.

A expressão lógica é diferente de expressões matemáticas. A expressão lógica só aceita dois operandos que podem ser id, numero (e _Z_) entre os operadores maior, menor, igual, diferente, Migual e migual:

enquanto Teste maior _Z_.
inicio.
comandos e expressões válidas
fim.

  • enquanto Teste > 30. é erro léxico pois > não faz parte da gramática
  • enquanto 30 x 40. é erro sintático porque não pode operadores matemáticos como expressão do enquanto
  • enquanto Teste maior $Soma(20, 30) é erro sintático porque não pode função como operando
  • enquanto Teste maior _Z_ igual Lixo erro sintático porque só pode ter dois operandos

OBS: estou dando exemplos de erros sintáticos usando o código fonte, mas lembre-se que o analisador sintático não olha o código fonte. Ele não vê e não analisa Teste, mas sim o token <id> (se usaram esta nomenclatura). Algo como:

enquanto Teste   maior   _Z_    .

<res,1> <id,40> <rel,6> <res,2>  <pont,30>   OU

<res,1> <id,40> <rel,6> <num,40> <pont,30>

<res> seria token para palavra reservada e <rel> seria token para operador relacional.

Não tem problema identificar _Z_ como num, pois é mesmo um num. Só terá que ter na tabela de símbolos o valor 0 para este num. Ter a palavra reservada _Z_ para o número 0 é apenas porque foi definido que um número não pode começar com 0.

para

O para requer sempre um identificador contador e um limite que pode ser um numero ou outro identificador.

inicio .

fim .

DECIMAL Limite .
Limite = 30 .
para Contar Limite.
inicio .

fim .

O segue a mesma lógica do enquanto. entao e senao são apenas palavras reservadas. Necessariamente deve ter sempre o senao, mesmo que vazio. Vazio significa não ter comandos.

inicio.

   Teste = 45 x Lixo.
fim.

inicio.
fim.

Erros léxicos

Sempre que não pode ser identificado como token válido. Caracteres que não fazem parte da linguagem, como <, >, etc.

Uma palavra lixo por exemplo é erro léxico, porque não pode ser id e nem função. Logo não é token algum. Erro léxico.

Erros sintáticos

Devem dizer em qual linha do código fonte ocorreu o erro.

Alguns tokens são solitários, só seguidos por ., como entao, senao, inicio, fim.

Pegos pelo não casamento com nenhuma regra de produção.

Não é necessário que a ferramenta diga qual erro, apenas que tal linha tem erro.

Erros semânticos

Serão tratados apenas teoricamente. Não deve implementar.

São erros como a não definição de uma função ou variável, a falta de inicio, fim, etc.
